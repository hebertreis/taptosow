## Design Context

### Users
OneTapGo serves two closely related contexts:

- Field operators and technicians who provision NFC tags quickly and repeatedly during setup or operations.
- Church staff and admins who use the broader platform to connect physical tags to church giving flows.

The product must support fast, low-friction task completion in real environments while still feeling trustworthy and appropriate for a church giving platform. Across both the mobile web admin UI and the device OLED/LCD UI, the core job is to help users configure, write, verify, and monitor NFC interactions with minimal confusion and minimal delay.

### Brand Personality
Brand personality:

- trustworthy
- practical
- welcoming

The interface should communicate confidence and clarity without looking geeky, cinematic sci-fi, or like a developer tool such as VS Code. The current repo includes a strong high-speed operational direction, but that energy should be moderated so the product still feels appropriate for church giving rather than a hacking or terminal aesthetic.

### Aesthetic Direction
Design for both the mobile admin experience and the device display.

Use the repo's existing emphasis on speed, legibility, and operational clarity, especially for field workflows, but avoid pushing the visual language into overt sci-fi or "tech fantasy" territory. Favor clean, high-contrast, modern interfaces that can work in both light mode and dark mode. The device UI should stay extremely functional and readable at a glance. The mobile/admin UI can feel sharper and more polished, but should remain approachable and calm enough for a church-facing product.

Anti-references:

- geeky hacker aesthetics
- sci-fi movie interfaces
- VS Code-inspired visual language

### Design Principles
1. Prioritize speed and clarity for repeated operational tasks such as scanning, writing, reading, and status verification.
2. Balance technical confidence with warmth so the product feels appropriate for a church giving platform, not an engineering console.
3. Design every interface for immediate readability in the field, with strong hierarchy, clear states, and minimal ambiguity.
4. Support both light mode and dark mode intentionally rather than treating one as a weak fallback.
5. Keep hardware surfaces utilitarian and concise, while allowing companion web surfaces to carry more polish and brand expression.
